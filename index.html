// why

Why it exists

Because a DNS-only filter is one wrong setting away from being useless. A browser with Secure DNS, or any VPN, resolves names outside your filter — and the block silently stops working.

The hosts file sits below all of that. The operating system checks it before any name resolution, so the block holds no matter what tunnels or resolvers you use. That is the whole point of two layers.

// usage

Three steps

  1. BloBlocker.zip — extract, keep the folder intact
  2. run BloBlocker.exe, accept the Administrator prompt
  3. press Activate — protection is live

BloBlocker.exe must stay next to its _internal folder; moving it alone breaks the app.

// faq

Questions

Does it collect data?

No. Everything runs locally; the app never opens a connection.

Can a VPN attack the block?

It can slip past the DNS layer but not the hosts layer, which the OS honors before any network call.

Why does it ask for Administrator?

Editing the hosts file and system DNS settings requires elevated rights.

Windows flags the download as a virus?

It is a false positive common with unsigned Python-built executables. The onedir + zip build reduces it; see the Microsoft submission note in the README.
